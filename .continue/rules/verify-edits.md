# 编辑文件后强制自校验

本规则用于杜绝“AI 声称已修改文件、实际未改动”的幻觉问题。每次使用编辑/写入工具修改文件后，**必须**执行以下校验，确认生效后才可向用户报告“已完成”：

1. **写后立即回读**：用 read 工具重新读取刚修改的文件，确认目标内容（例如 `actions/checkout@v5`）确实存在于文件中。
2. **批量多文件修改**：每改完一个文件就回读一次；全部改完后，用 grep 在整个项目内搜索旧值（例如 `checkout@v4`），确认命中数为 0，才算真正完成。
3. **若回读发现未生效**：不要重复声称成功，而是立即重试编辑；若工具连续失败，明确告知用户“未能应用修改”，并给出需要手动修改的具体文件与位置。
4. **先验证、后汇报**：严禁仅凭“意图/计划”报告成功。先实际校验文件，再向用户汇报结果。
5. **与 OpenCode 接力时**：改动后务必 `git status` / `git diff` 自查，确保落盘；涉及 GitHub 交付的变更，确认已提交/推送后再声明完成。
