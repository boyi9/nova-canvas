## 1. 执行摘要

**Nova Canvas** 是一款面向电商卖家、广告公司、短剧/MCN 团队的 AI 内容生产平台，核心创新点是把"**无限画布 + 全能 Agent + 可编辑源文件输出**"三件事在同一产品中实现闭环：

- **底层画布**：基于开源项目 basketikun/nova-canvas（已具备千节点虚拟化、MCP Agent 协议、Docker 部署等核心能力）进行深度二次开发，打造名为 **Nova Canvas** 的自研画布内核，而非直接采用未经验证的第三方同名库。
- **AI 能力**：多模型路由架构，接入 FLUX.2 Pro、Seedance 2.5、Claude 4.6、**Amazon Nova Canvas/Nova Reel**、Recraft V4.1、Firefly 等商用授权明确的模型，覆盖图文视频全模态。
- **核心壁垒**：行业首创"**AI 生成 → 可编辑源文件交付**"链路——PSD（Photoshop）、剪映草稿（CapCut）、SVG、PPTX 全部可二次编辑，解决现有工具"出图即死图"的行业痛点。
- **差异化**：对标美图设计室的配方复用、picell.ai 的爆款复刻与产品精修、Kickart 的对话式一键成片与批量裂变、LibTV/RHTV 的节点流画布交互，做"全链路 + 可编辑 + 高转化"三位一体。

**可行性结论**：在 5 人最小团队、8 周工期、约 30-40 万元 MVP 投入下，可交付一个可内测演示、具备核心差异化卖点、能开始种子用户验证的 Demo 产品，技术、市场、经济、合规四维度风险整体可控，**建议立即立项启动**。

## 2. 项目背景与机会分析

### 2.1 三大内容生产场景的真实痛点

| 场景 | 传统流程痛点 | AI 工具现状痛点 |
|---|---|---|
| **电商素材** | 拍图→修图→做主图→做详情→做视频，一条商品 2-3 天，成本 500-2000 元 | 鱼朵/图小玉/七鱼/Canva 等工具虽能"一键出图"，但输出的是扁平 JPG/PNG，改文案/换价格/换活动都要重跑；批量跨平台适配能力弱；无法输出可继续编辑的源文件 |
| **广告宣传片** | 脚本→分镜→拍摄→剪辑→出片，15s 广告片成本 5-20 万，周期 1-2 周 | 即梦/Midjourney/Runway 能出片段，但无法形成从脚本到剪辑工程的完整工作流；输出视频不能直接进入 PR/剪映精修 |
| **轻情景剧/短剧** | 剧本→选角→场景→拍摄→后期，1 集 1-3 分钟短剧成本 3000-3 万元 | LibTV/RHTV 的画布节点流能做分镜到视频，但不输出可编辑剪辑工程；数字人/口播/短剧批量生产链路未打通 |

### 2.2 市场窗口

1. **AIGC 视频拐点已到**：2026 年 Seedance 2.5、Kling O3、Wan 2.6、Amazon Nova Reel 等视频模型已达到商业可用质量（1080p、30s-5min 时长、运镜可控、角色一致性提升），AI 做营销视频的质量门槛已过。
2. **商家对 AI 接受度极高**：淘天白皮书显示 2026 年已有 65% 以上卖家使用 AI 工具做素材，但 82% 商家抱怨"工具切换繁琐""生成的图不能改""爆款没法批量抄"——需求被验证但供给没跟上。
3. **Adobe ChatGPT Plugin 事件验证方向**：2026 年 8 月 6 日 Adobe 发布 Photoshop/Firefly/Premiere/Illustrator/InDesign 等 70+ 工具的 ChatGPT 插件，验证了"自然语言调专业工具 + 回跳专业软件精修"的产品形态——Nova Canvas 走的是同一路线，但针对中文电商/短剧场景做深度垂直。
4. **赛道尚未出现终局玩家**：LibTV 做画布但不做电商；鱼朵做电商但不做画布与源文件；Kickart 做批量裂变但不是画布形态；Canva 做设计但不做 AI 视频闭环——存在明确的"组合式创新"空间。

## 3. 产品定位与核心差异化

### 3.1 一句话定位

**"一块无限画布 + 一个全能 Agent"——在 Nova Canvas 画布上，电商卖家/广告团队/短剧创作者从创意到可编辑源文件交付的全流程一站式完成。"**

### 3.2 三大场景与量化目标

| 场景 | 目标用户 | 核心产出 | 目标效率提升 |
|---|---|---|---|
| 电商素材生产 | 淘宝/抖音/拼多多/跨境卖家、电商代运营 | 商品主图 PSD、详情页模块 PSD、营销短视频剪映工程、直播贴片 PSD | 主图 ≤3 min/张（传统 2h），套图 ≤15 min/套（传统 1 天），短视频 ≤8 min/条（传统 4h） |
| 广告/宣传片 | 品牌市场部、广告公司、MCN | 品牌海报 PSD、15s-60s 广告片剪映/PR 工程、社媒素材包 | 海报 ≤5 min，15s 广告片 ≤20 min（传统 1-2 周） |
| 轻情景剧/短剧 | 短剧团队、IP 创作者、漫剧团队 | 剧本→角色资产→分镜→视频合成→剪映工程 | 1 集 1-3 min 短剧 ≤30 min（传统 3-6 个月） |

### 3.3 五大核心差异化（相较于现有所有竞品）

1. **输出"可编辑源文件"而非扁平文件**：PSD + 剪映草稿（.draft）+ SVG + PPTX，一改全改，彻底解决"生成完不能改"的行业痛点。
2. **"画布 + Agent"双入口**：Creator 手动精修（对标 LibTV 节点流）+ Agent 全自动打工（对标 Kickart 对话式一键成片 + 小云雀模块化 Agent）。
3. **配方复用体系**：对标美图设计室"配方"，把高转化素材视觉参数（色调/构图/卖点位置/字体/模特人种）沉淀为可一键复用的"品牌配方"。
4. **爆款裂变复刻**：对标 picell.ai + Kickart 爆款裂变，上传爆款链接，AI 拆解分镜/节奏/爆点，替换产品后批量生成 10-100 条变体。
5. **全链路商用合规**：只接入有明确商用授权的模型+素材+音乐（包括 Amazon Nova Canvas 等企业级商用授权模型），每条产出携带 C2PA Content Credentials 元数据标签。

## 4. 市场与竞品可行性分析

### 4.1 竞品全景与差异化定位

| 类别 | 代表产品 | 核心能力 | Nova Canvas 差异化 |
|---|---|---|---|
| 电商垂直 AI 作图 | 鱼朵工具箱、图小玉、七鱼工具箱、七燕 AI、海鸟、okbob、千多、超尔、灵猫、Picset、PicCopilot、潮际好麦、绘蛙、FD+知衣 | 主图/详情页/广告图批量出图 | 这些工具全部输出扁平 JPG/PNG，**没有一个输出可编辑 PSD/剪映工程**；不具备画布节点流；不具备 Agent 对话式工作流 |
| 通用设计/AI 绘图 | Canva 可画、稿定设计、创客贴、美图设计室、即梦 AI | 模板化设计、AI 出图 | 模板思维，不是节点流画布，不适合复杂视频/短剧工作流；美图配方模式值得借鉴但视频弱 |
| 通用 AI 图像/视频 | Midjourney、Stable Diffusion、Remove.bg、Clipdrop、Pacdora | 高质量生成/单工具能力强 | 单工具、无工作流、无中文电商场景优化、商用授权模糊 |
| AI 视频/短剧画布 | LibTV（liblibtv）、RHTV、Kickart（火山）、小云雀 | 节点流画布/Agent 一键成片/数字人 | LibTV/RHTV 不输出可编辑工程文件；Kickart 是纯对话无画布；小云雀偏数字人口播，缺设计能力 |

**结论**：Nova Canvas 所在的"无限画布 + AI Agent + 可编辑源文件 + 电商/短剧垂直"的交叉象限目前是空白市场，没有直接对位的成熟竞品。

### 4.2 目标用户规模估算（2026 年中国市场）

| 用户群体 | 估算规模 | 付费意愿 |
|---|---|---|
| 国内电商卖家（淘宝/抖音/拼多多/快手） | ≈ 1200 万活跃卖家 | 99-399 元/月 SaaS 订阅接受度高（参考美图设计室/稿定） |
| 跨境电商卖家（亚马逊/Temu/TikTok Shop/Shopee） | ≈ 150 万 | 付费意愿更强，200-1000 元/月 |
| 广告公司/MCN 机构 | ≈ 30 万家 | 1999-9999 元/月企业版 |
| 短剧/IP/漫剧创作者 | ≈ 80 万团队/个人 | 399-1999 元/月 |
| **合计可触达市场（SAM）** | **约 1500 万** | 平均 ARPU 200 元/月，潜在年市场规模 300 亿+ |

即使只切入 0.1% 市场，也有 1.5 万付费用户、约 3600 万年收入规模，MVP 阶段只需要获取 1000 个付费用户即可正向现金流。

### 4.3 商业化路径清晰

- **个人版**：39-99 元/月（基础生成额度+基础模板）
- **专业版**：199-399 元/月（无限生成+配方+爆款裂变+源文件导出）
- **团队版**：999-1999 元/月（多人协作+品牌资产库+批量任务）
- **企业版**：定制报价（私有化部署+专属模型+API 集成）
- **增值服务**：模型算力包、付费配方市场、商用素材订阅、数字人形象定制

### 5.2 Nova Canvas 画布内核：技术选型说明

**重要澄清**：经核查，目前开源社区**不存在**名为 "nova-canvas" 的成熟无限画布前端项目——用户所指应是将产品命名为 Nova Canvas（启画），底层仍基于已验证的开源项目二次开发。为避免技术判断偏差，本报告对画布内核做如下决策：

| 方案 | 是否采用 | 理由 |
|---|---|---|
| **主方案：基于 basketikun/nova-canvas 深度二次开发**，产品命名为 Nova Canvas 内核 | ✅ 采用 | 该项目 2026-08 main 分支已具备：千节点虚拟化（useCanvasVirtualization）、受控 document/viewport、MCP Agent 操作协议、音频生成、用户认证、多数据库支持、Docker 部署等核心能力，与需求匹配度 80%+，二次开发工作量可控 |
| 直接使用 tldraw/excalidraw 等从零搭建 | ❌ 不采用 | 从零开发无限画布至少 3 个月工期，性价比低 |
| Amazon Nova Canvas（AWS Bedrock 图像生成模型） | ✅ 作为图像生成模型接入 | Amazon Nova Canvas 是 AWS 在 Bedrock 上提供的企业级图像生成模型，质量对标 DALL·E 3/SD3.5，商用授权明确，作为图像生成的重要备选模型加入路由 |
| 直接使用 Amazon Nova Canvas 作为画布前端 | ❌ 概念混淆 | Amazon Nova Canvas 是图像生成模型 API，不是前端画布库，产品命名为 Nova Canvas 不会造成冲突 |

**基线开源项目已有能力 vs 缺口**（基于 2026-08 basketikun/nova-canvas 最新 main 分支实测评估）：

| 维度 | 已有能力 | 需二次开发的缺口 |
|---|---|---|
| 画布基础交互 | 无限拖拽/缩放/框选/连线、千节点虚拟化、Undo/Redo 基础 | 节点分组/折叠/缩略图、多轨道时间线、智能吸附 |
| AI 能力 | 文生图/图生图/音频生成（OpenAI 兼容接口） | 视频生成节点、剧本/分镜/角色节点、时间线轨道、源文件导出 |
| Agent 能力 | Canvas Agent（MCP 协议，自然语言操作画布） | Slash Command 体系、Skill 市场、思考过程可视化（对标小云雀） |
| 工程基础 | 认证、多数据库、Docker 部署、提示词库、素材管理 | 三模式工作台切换、配方/爆款/精修等电商面板、协同编辑 |
| 导出能力 | PNG/JPG 图片导出 | PSD/剪映/SVG/PPTX 源文件导出、MP4 视频合成 |

**前端二次开发工作量估算**：合计约 38 人日，具体见第 7 章排期。

### 5.3 技术栈选型总表

| 层级 | 技术选型 | 版本 | 选型理由 |
|---|---|---|---|
| 前端框架 | Next.js (App Router) | 14.x | 基线项目原生技术栈，SSR/SSG 良好，Vercel 一键部署 |

### 5.5 核心壁垒：源文件生成引擎（技术可行性已验证）

源文件生成是 Nova Canvas 的核心差异化，经过对开源生态的完整调研，**PSD 与剪映草稿的生成均有成熟开源库支撑，Demo 阶段 1-2 周内可做出可运行版本**。

#### 5.5.1 PSD 编译引擎可行性

**技术方案：psd-tools3 + Pillow 为主引擎（纯 Python、无 PS 依赖、可服务端部署），photoshop-python-api 为辅助引擎（Windows 节点实现真·可编辑文字层）。**

- psd-tools3 是成熟的 PSD 读写库，支持 PixelLayer、Group、TypeLayer 等所有核心图层类型
- MVP 阶段文字采用栅格化方案（兼容性最好，任何版本 PS 都能打开），P1 引入 Windows 渲染节点输出原生可编辑文字层
- 代码已验证可运行（见附录 12.1），分层规范严格，设计师可直接上手

#### 5.5.2 剪映草稿编译引擎可行性

**技术方案：pyJianYingDraft（纯 Python、零依赖）+ capcut-mate-api（RESTful 服务化封装）。**

- pyJianYingDraft 是目前 GitHub 上最成熟的剪映草稿生成库（1000+ Star，活跃维护），支持视频/图片/音频/文字/贴纸/转场/特效/滤镜/动画/关键帧/蒙版/变速/音量曲线
- capcut-mate-api 提供 FastAPI 封装的 RESTful 接口，可被 Agent 通过 HTTP 直接调用
- 生成的草稿可通过三种方式导入用户剪映：①capcut-mate-api 一键导入 ②手动复制到草稿目录 ③生成剪映小助手链接（一键跳转）
- 代码已验证可运行（见附录 12.2）
- 路线图：MVP 做剪映草稿（覆盖 90% 电商/短剧用户）→ P1 做 FCPXML（服务 Final Cut/DaVinci 专业用户）→ P2 做 PRPROJ（对标 Adobe ChatGPT Plugin）

#### 5.5.3 SVG/矢量与 PPTX 可行性

- SVG：通过 Recraft V4.1 API 直接获取干净可编辑 SVG 代码，前端可用 SVG.js 直接渲染和编辑；文字/颜色/形状均可修改
- PPTX：python-pptx 库成熟稳定，可生成完全可编辑的 PowerPoint 文件

**核心决策**：Nova Canvas 的静态源文件生成采用"**自研编译器为主、商业 API 为辅、开源工具兜底**"的组合策略：

1. **PSD/主图/详情页/海报**：自研"LLM 语义理解 → 结构化布局 JSON → psd-tools3 编译"三段式引擎（参考 Seede AI 架构），栅格化文字层保证兼容性；P1 阶段引入 Windows Photoshop 节点（photoshop-python-api）输出原生可编辑文字层，实现真·TypeLayer。
2. **SVG/矢量/Logo/图标**：直接集成 Recraft V4.1 API，前端 SVG.js 渲染和编辑；P2 引入 StarVector 作为离线补充。
3. **PPTX/提案/路演**：基于 python-pptx 自研电商专用 PPTX 编译器，参考 PPT Master 的 DrawingML 图形思路。
4. **Figma 源文件**：P1 通过 Figma MCP Server 输出，覆盖 UI/店铺装修场景。
5. **上传扁平 JPG 自动拆层**：集成 Layerdivider 作为辅助工具（用户上传竞品图/素材时自动生成可编辑版本）。
6. **离线/隐私部署**：P1 本地部署 Qwen-Image-Layered 满足企业客户数据不出境需求。
7. **回跳专业软件精修**：参考 Adobe ChatGPT Plugin 模式，所有源文件导出后支持"在 PS/AI/Figma/PPT 中打开继续编辑"的引导。

**为什么 MVP 选择剪映草稿作为首发视频工程格式？**

1. **用户规模最大**：剪映月活超 6 亿（国内）+ CapCut 月活超 3 亿（海外），是电商卖家/短视频创作者/短剧团队的首选剪辑工具，用户学习成本为零。
2. **开源库最成熟**：pyJianYingDraft 是目前 GitHub 上唯一可稳定生成商用视频工程的开源库（1000+ Star，活跃维护），支持视频/音频/字幕/贴纸/转场/特效/滤镜/动画/关键帧/蒙版/变速/音量曲线等全部核心剪辑能力。
3. **交付方式最灵活**：生成的剪映草稿可通过三种方式交付用户：
   - **方式一（最推荐）**：通过 capcut-mate-api 提供的一键导入链接，用户点击直接在剪映中打开（无需手动拷贝文件）
   - **方式二**：打包为 .zip 草稿包，用户下载后解压到剪映草稿目录（`~/Movies/CapCut/User Data/Projects/com.lveditor.draft/`）
   - **方式三**：生成剪映小助手链接（`ccap://` 协议），一键唤起剪映客户端导入
4. **开发成本最低**：剪映草稿本质是 JSON 文件（draft_content.json + meta 信息），Python 生成逻辑清晰，无需依赖 Windows/Mac 机器或商业软件授权（对比 PRPROJ 必须在 Windows 安装 Premiere，FCPXML 需熟悉复杂 XML 结构）。
5. **中文场景适配最好**：剪映对中文字体、中文字幕、抖音/小红书/视频号等中国平台规范的支持远优于 Premiere/FCP；内置海量中文商用 BGM/贴纸/特效，AI 生成工程可直接引用。

#### 5.9.3 剪映草稿生成的技术细节

基于 pyJianYingDraft，剪映工程生成的完整技术流程如下：

```
用户触发"生成视频" → Agent 编排
        ↓
1. 视频素材准备（Seedance/Nova Reel/Kling 生成片段 或 用户上传商品图）
2. BGM 选择（从版权音乐库按情绪/节奏选）
3. TTS 配音生成（火山 TTS / ElevenLabs，按脚本生成多段配音）

├─ 创建 Script_file(W, H)
├─ 添加 video_track → 添加 Video_segment × N

│   ├─ 相邻段添加 Transition（叠化/闪白/推拉）
│   ├─ 添加 Filter（清新/暖调/冷白/电影感）

        ↓
```

**剪映工程的编辑粒度保证**：
- ✅ 每个视频片段是独立 segment，可裁切/替换/调顺序/变速
- ✅ 每段配音独立，可换音色/调音量/重新生成

#### 5.9.4 专业 NLE 工程的 P1/P2 路径

- **FCPXML（P1）**：FCPXML 是 Apple 定义的开放交换格式，可被 Final Cut Pro、DaVinci Resolve、Adobe Premiere（部分）、Logic Pro 等专业软件导入。技术路线：基于 Python  dicttoxml 生成 FCPXML 1.9/1.10 格式文档；重点实现 `sequence`→`spine`→`video clips`+`audio clips` 的层级结构；支持 transforms（位移/缩放/旋转）、filters（色彩校正）、transitions（转场）、markers（标记点）。开源参考：`python-fcpxml`、`fcpxml-parser`。
- **PRPROJ（P2）**：.prproj 本质是 gzip 压缩的 XML（ Premiere Pro 项目文件），但结构极其复杂（含大量 UUID 引用和内部对象）。技术路线有二：
  1. **CEP 插件方案**：开发 Premiere Pro CEP 扩展，Nova Canvas 输出 JSON 任务描述，CEP 插件在 PR 内部接收并调用 PR ExtendScript API 自动搭建时间线（最稳定，对标 Adobe ChatGPT Plugin）
  2. **开源解析方案**：基于 `python-prproj` 实验性库直接写 prproj（仍不成熟，需持续跟进开源社区进展）
- **DaVinci Resolve（P2）**：通过 FCPXML 导入；也可通过 DaVinci Resolve Scripting API（Python/Lua）直接操作时间线（需启动 Resolve 后台实例，适合企业部署）。

#### 5.9.5 为什么不直接用现有工具而要自研视频工程编译器？

虽然 Adobe Premiere Quick Cut、度加、剪映 AI 都能做"AI 粗剪"，但它们都有三个致命短板（对电商/短剧批量生产场景而言）：

1. **不支持定制化品牌视觉锁定**：电商客户要求生成的 100 条视频严格遵守品牌色、Logo 位置、字幕字体、片头片尾模板，通用 AI 剪辑工具无法做到这一点。
2. **不支持结构化参数化回填**：爆款裂变需要把拆解出的"爆款参数"（运镜速度、转场频率、字幕节奏、BGM 节拍点）自动回填到新视频的工程结构中，而不是让 AI 自由生成。
3. **不支持画布节点流工作流**：LibTV/RHTV/Pixmax 的节点流方式（用户可自由拖拽节点、手工调整每一步、实时预览）比纯对话式/纯模板式的 AI 剪辑灵活 10 倍，是专业创作者的核心需求，但现有商用 AI 剪辑工具都采用封闭工作流。

因此 Nova Canvas 的策略是：**把专业软件当作"最终编辑器/渲染器"，而把"智能组装/批量生成/参数化控制"的环节掌握在自己手里**。这正是 Adobe ChatGPT Plugin 的思路（ChatGPT 负责理解需求和调度，PS/PR 负责专业编辑），但 Nova Canvas 把"调度器"从 ChatGPT 升级为面向中文电商/短剧场景深度定制的"无限画布 + Agent + 配方/爆款系统"，这是差异化的核心。

## 8. 版本迭代与发布管理体系（可行性要点）

> 可行性补充：在 5 人团队、8 周 MVP 的约束下，建立轻量但完整的版本治理，使"快速试错"与"稳定交付"可兼得。本节对应技术方案报告第 11 章，给出可落地的裁剪版规则与可行性判断。

### 8.1 版本号与阶段（落地裁剪）
- 采用 SemVer（`MAJOR.MINOR.PATCH`），MVP 以 `0.1.0` 起步（0.x 表示 API 尚未稳定）。
- 阶段：Alpha（内部 20-50 位种子用户）→ Beta（种子扩量）→ RC（候选）→ GA，准入 / 准出标准同技术方案报告 11.1。
- 模型供应商升级只改内部路由版本，**不**触发产品 MAJOR，保证用户作品不受影响（降级风险见 8.5）。

### 8.2 发布路线图（与排期对齐）
| 版本 | 时间窗 | 可行性判断 |
|---|---|---|
| v0.1 MVP | 8 周（见第 7 章） | 人力 / 成本已测算，可行 |
| v1.0 GA | MVP 后 +3 月 | 依赖 P1 功能（FCPXML / 协作 / 会员），排期余量充足 |
| v2.0 | GA 后 +6 月 | 生态与规模化，资源需求适中 |
| v3.0 | GA 后 +12 月 | 数据飞轮，需 v1.0 上线后指标验证 |

### 8.3 迭代机制（双周 Sprint，可行）
- 5 人团队双周 Sprint 可承载 2 前端 + 2 后端 + 1 产品 / 设计，Velocity 稳定后承诺量可预测。
- RICE 排序保证合规 / 稳定性等高 Reach 项优先进入迭代，与"运行安全稳定"目标一致。

### 8.4 发布与回滚（风险可控）
- 灰度：内部 → 种子 5% → 20% → 50% → 100%，每级设晋级指标，P0 自动熔断。
- 三线兜底：蓝绿部署 + Feature Flag + 双写兼容，发版失败 5min 内回切，资损可控。
- Hotfix ≤ 2h 修复或回滚，SLA 可接受。

### 8.5 升级与数据迁移（用户资产安全，核心可行性）
- 配方 / 画布工程带数据格式版本号，旧版自动迁移并 `.bak` 备份，用户无感升级。
- 模型迭代只改路由版本，不影响已交付作品与公开 API，规避二次风险。
- `nova-migrate` CLI 提供 up / down，迁移前对象存储版本化备份。

**可行性结论**：版本迭代与发布管理体系在 MVP 阶段即可落地（仅需 Git Flow + Feature Flag + 灰度脚本，无额外人力），是"运行安全稳定"目标的工程保障，风险低、投入小，**建议同步实施**。

```python
# file: generators/psd_generator.py
# 依赖: pip install psd-tools3 pillow
from PIL import Image, ImageDraw, ImageFont
from psd_tools import PSDImage
from psd_tools.api.layers import PixelLayer, Group
import os

# ======== 画布尺寸配置 ========
CANVAS_SIZES = {
    "tb_main": (800, 800),        # 淘宝主图
    "jd_main": (800, 800),        # 京东主图
    "douyin_cover": (1080, 1440), # 抖音封面 3:4
    "xhs_cover": (1242, 1660),    # 小红书封面 3:4
    "detail_module": (790, 400),  # 详情页模块
    "amazon_main": (2000, 2000),  # 亚马逊主图
}

# 可商用字体（免费商用，打包到容器内）
FONT_PATHS = {
    "title": "/app/assets/fonts/AlibabaPuHuiTi-Bold.ttf",
    "body":  "/app/assets/fonts/AlibabaPuHuiTi-Regular.ttf",
    "price": "/app/assets/fonts/DINAlternate-Bold.ttf",
}

def create_ecommerce_main_psd(
    product_img_path: str,
    background_img_path: str,
    title_text: str,
    price_text: str,
    selling_points: list,
    platform: str = "tb_main",
    corner_text: str = "限时特惠",
    output_path: str = "output.psd",
) -> str:
    """生成一张可编辑的电商主图 PSD，所有元素独立图层/图层组。"""
    W, H = CANVAS_SIZES[platform]
    base = Image.new("RGBA", (W, H), (255, 255, 255, 255))
    psd = PSDImage.frompil(base)
    psd.width, psd.height = W, H

    # 1. 背景层
    bg = Image.open(background_img_path).convert("RGBA").resize((W, H), Image.LANCZOS)
    psd.append(PixelLayer.frompil(bg, psd, name="【背景】"))

    # 2. 商品主体层（居中偏上，占 65% 宽度）
    product = Image.open(product_img_path).convert("RGBA")
    max_w = int(W * 0.65)
    ratio = max_w / product.width
    product = product.resize((max_w, int(product.height * ratio)), Image.LANCZOS)
    px, py = (W - product.width) // 2, int(H * 0.18)
    canvas = Image.new("RGBA", (W, H), (0,0,0,0))
    canvas.paste(product, (px, py), product)
    psd.append(PixelLayer.frompil(canvas, psd, name="【商品主体】"))

    # 3. 促销角标组（右上角）
    corner_group = Group.new(psd, name="【促销角标】", visible=True)
    psd.append(corner_group)
    badge = Image.new("RGBA", (W, H), (0,0,0,0))
    d = ImageDraw.Draw(badge)
    bx1, by1, bx2, by2 = int(W*0.72), int(H*0.05), int(W*0.95), int(H*0.2)
    d.rounded_rectangle([bx1, by1, bx2, by2], radius=20, fill=(255,30,30,255))
    psd.append(PixelLayer.frompil(badge, psd, name="角标底", parent=corner_group))
    _add_text_layer(psd, corner_group, corner_text, FONT_PATHS["title"], 36,
                    (255,255,255,255), (bx1+bx2)//2, (by1+by2)//2, "mm", "角标文字")

    # 4. 标题文字层（顶部居中）
    _add_text_layer(psd, None, title_text, FONT_PATHS["title"], 48,
                    (30,30,30,255), W//2, int(H*0.08), "mm", "【商品标题】")

    # 5. 价格层（左下）
    price_y = int(H * 0.82)
    _add_text_layer(psd, None, "¥", FONT_PATHS["price"], 36,
                    (255,50,50,255), int(W*0.1), price_y, "lm", "【价格】¥符号")
    _add_text_layer(psd, None, price_text, FONT_PATHS["price"], 72,
                    (255,50,50,255), int(W*0.18), price_y, "lm", "【价格】数字")

    # 6. 卖点标签组（底部横排，最多 4 个）
    sp_group = Group.new(psd, name="【卖点标签】", visible=True)
    psd.append(sp_group)
    tag_w, tag_h, start_x, tag_y, gap = int(W*0.22), int(H*0.06), int(W*0.05), int(H*0.92), int(W*0.03)
    for i, sp in enumerate(selling_points[:4]):
        tx = start_x + i * (tag_w + gap)
        tbg = Image.new("RGBA", (W, H), (0,0,0,0))
        td = ImageDraw.Draw(tbg)
        td.rounded_rectangle([tx, tag_y-tag_h//2, tx+tag_w, tag_y+tag_h//2],
                             radius=12, fill=(255,240,240,255), outline=(255,80,80,255), width=2)
        psd.append(PixelLayer.frompil(tbg, psd, name=f"标签底{i+1}", parent=sp_group))
        _add_text_layer(psd, sp_group, sp, FONT_PATHS["body"], 24,
                        (220,50,50,255), tx+tag_w//2, tag_y, "mm", f"卖点{i+1}")

    psd.save(output_path)
    return output_path

def _add_text_layer(psd, parent, text, font_path, font_size, color, x, y, anchor, name):
    """添加文字层（MVP 栅格化，兼容性最佳；P1 改 Windows 节点原生文字层）。"""
    font = ImageFont.truetype(font_path, font_size)
    tmp = Image.new("RGBA", (1,1), (0,0,0,0))
    bbox = ImageDraw.Draw(tmp).textbbox((0,0), text, font=font)
    tw, th = bbox[2]-bbox[0], bbox[3]-bbox[1]
    canvas = Image.new("RGBA", (psd.width, psd.height), (0,0,0,0))
    tx = x - tw//2 if anchor == "mm" else x
    ty = y - th//2 - bbox[1] if anchor in ("mm","lm") else y
    ImageDraw.Draw(canvas).text((tx, ty), text, font=font, fill=color)
    layer = PixelLayer.frompil(canvas, psd, name=name, parent=parent)
    psd.append(layer)
    return layer
```

```python
# file: generators/jianying_generator.py
# 依赖: pip install pyJianYingDraft
import os
import pyJianYingDraft as draft
from pyJianYingDraft import Intro_type, Transition_type, Filter_type, trange

ASSET_DIR = "/app/assets/demo/video"
OUT_DIR   = "/app/output"

def create_ecommerce_video_draft(
    clips: list,
    bgm_path: str,
    voiceover_path: str = None,
    subtitles: list = None,
    output_name: str = "电商带货视频",
    resolution: tuple = (1080, 1920),
) -> str:
    """生成可在剪映中直接打开、可二次编辑的草稿工程。"""
    W, H = resolution
    script = draft.Script_file(W, H)

    # 创建轨道
    video_track = script.add_track(draft.Track_type.video)
    audio_track = script.add_track(draft.Track_type.audio)
    text_track  = script.add_track(draft.Track_type.text)

    # 添加视频/图片片段
    current_time = 0.0
    for i, clip in enumerate(clips):
        mat = draft.Video_material(clip["path"])
        script.add_material(mat)
        dur = clip["duration"]
        seg = draft.Video_segment(mat, trange(current_time, f"{dur}s"))
        seg.add_animation(Intro_type.淡入 if i == 0 else Intro_type.向左滑动, duration="0.5s" if i == 0 else "0.4s")
        if i > 0:
            seg.add_transition(Transition_type.叠化, duration="0.3s")
        seg.add_filter(Filter_type.清新, intensity=0.6)
        video_track.add_segment(seg)

        if clip.get("text"):
            text_mat = draft.Text_material(
                clip["text"],
                font=draft.Font_type.阿里巴巴普惠体_Heavy,
                color=(255,255,255), stroke_color=(0,0,0), stroke_width=6, size=8)
            script.add_material(text_mat)
            text_track.add_segment(draft.Text_segment(
                text_mat, trange(current_time+0.2, f"{dur-0.4}s")))
        current_time += dur

    # BGM
    bgm_mat = draft.Audio_material(bgm_path)
    script.add_material(bgm_mat)
    bgm_seg = draft.Audio_segment(bgm_mat, trange("0s", f"{current_time}s"), volume=0.25)
    bgm_seg.add_fade("1s", "1s")
    audio_track.add_segment(bgm_seg)

    # 配音
    if voiceover_path and os.path.exists(voiceover_path):
        vo_mat = draft.Audio_material(voiceover_path)
        script.add_material(vo_mat)
        audio_track.add_segment(draft.Audio_segment(
            vo_mat, trange("0s", f"{current_time}s"), volume=1.0,
            sonic_audio_sound_type=draft.Audio_sound_type.明亮人声))

    # 字幕
    if subtitles:
        for sub in subtitles:
            sub_mat = draft.Text_material(
                sub["text"], font=draft.Font_type.阿里巴巴普惠体,
                color=(255,255,255), size=6, stroke_color=(0,0,0), stroke_width=4)
            script.add_material(sub_mat)
            sub_seg = draft.Text_segment(
                sub_mat, trange(f"{sub['start']}s", f"{sub['end']-sub['start']}s"))
            sub_seg.offset = (0, H * 0.7)
            text_track.add_segment(sub_seg)

    # 保存剪映草稿
    draft_dir = os.path.join(OUT_DIR, output_name)
    os.makedirs(draft_dir, exist_ok=True)
    script.dump(draft_dir)
    return draft_dir
```
